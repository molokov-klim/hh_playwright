# hh_auto_responder - Автоматизация откликов на hh.ru

Скрипт для автоматизации массовых откликов на hh.ru. Авторизуется на сайте под вашим аккаунтом, переходит к
рекомендациям по вашему резюме и отправляет отклики на все предложенные вакансии.

## Особенности

- Использование Playwright для автоматизации браузера
- Поддержка headless режима для работы в CI/CD
- Обход простых анти-бот проверок
- Детальное логирование всех действий с использованием loguru и декоратора log_info
- Обработка ошибок и создание скриншотов при проблемах
- Совместимость с GitHub Actions
- Интеграция с Telegram для получения уведомлений и отчетов об ошибках
- Поддержка команд бота для получения статуса системы

## Требования

- Python 3.10+
- `uv` для управления зависимостями

## Установка и настройка

1. Клонируйте репозиторий:

```bash
git clone <URL_репозитория>
cd hh_playwright
```

2. Создайте виртуальное окружение и установите зависимости:

```bash
uv venv
source .venv/bin/activate  # На Linux/Mac
# или
.venv\Scripts\activate  # На Windows

uv pip install -r requirements.txt
```

3. Установите браузеры Playwright:

```bash
uv run playwright install chromium
```

4. Установите переменные окружения:

Создайте файл `.env` или используйте переменные окружения:

```bash
export HH_LOGIN=ваш_email_или_телефон
export HH_PASSWORD=ваш_пароль
export FAKE=false  # Установите в true, чтобы запустить в режиме без реальных откликов
```

## Запуск скрипта

Для локального запуска:

```bash
uv run python hh_auto_responder.py
```

Для запуска в headed режиме (для отладки):

```bash
# Измените значение HEADLESS в конфигурации на False
```

Для запуска в режиме без реальных откликов (тестирование):

```bash
export FAKE=true
uv run python hh_auto_responder.py
```

## Режим FAKE

Новый режим `FAKE` позволяет запускать скрипт без отправки реальных откликов:
- При `FAKE=true` кнопка "Откликнуться" не нажимается
- Скрипт имитирует выполнение всех действий
- Это позволяет тестировать логику без отправки реальных откликов
- В логах будет отображаться статус "Успешно (FAKE)" вместо "Успешно"

## Переменные окружения

| Переменная | Описание | Обязательная |
|------------|----------|--------------|
| HH_LOGIN | Email или телефон для входа на hh.ru | Да |
| HH_PASSWORD | Пароль для входа на hh.ru | Да |
| FAKE | Если true, реальные отклики не отправляются (кнопка "Откликнуться" не нажимается) | Нет (по умолчанию false) |
| HEADLESS | Режим без GUI (true/false) | Нет (по умолчанию true) |
| VIEWPORT_WIDTH | Ширина окна браузера | Нет (по умолчанию 1920) |
| VIEWPORT_HEIGHT | Высота окна браузера | Нет (по умолчанию 1080) |
| USER_AGENT | User agent строка | Нет (по умолчанию задан) |
| TIMEOUT | Таймаут ожидания в миллисекундах | Нет (по умолчанию 30000) |
| RESUME_ID | ID резюме (опционально, будет определен автоматически) | Нет |
| TELEGRAM_BOT_TOKEN | Токен Telegram бота для уведомлений | Нет |
| TELEGRAM_CHAT_ID | ID чата для отправки уведомлений в Telegram | Нет |

## Режимы работы браузера

Скрипт может работать в двух режимах:

1. **Headless режим** (по умолчанию): Браузер работает без графического интерфейса. Установите `HEADLESS=true` или не устанавливайте переменную (по умолчанию true).
2. **Headed режим**: Браузер запускается с графическим интерфейсом. Установите `HEADLESS=false`.

> **Важно**: В headed режиме (HEADLESS=false) браузер будет отображаться только если у вас есть доступ к графическому серверу (X-сервер). В средах без GUI (например, в SSH-сессиях, в облаке или в CI/CD) headed режим может не работать корректно, и браузер будет запускаться в headless режиме независимо от значения переменной.

## Настройка GitHub Actions

В репозитории уже настроены следующие workflows:

1. `test.yml` - запускает тесты при пуше и пулл-реквестах
2. `run-hh-bot.yml` - запускает основной скрипт, может быть запущен вручную или по расписанию

Для настройки GitHub Actions:

1. В настройках репозитория создайте следующие секреты:
    - `HH_LOGIN` - ваш логин на hh.ru
    - `HH_PASSWORD` - ваш пароль на hh.ru
    - `TELEGRAM_BOT_TOKEN` - токен вашего Telegram бота (опционально)
    - `TELEGRAM_CHAT_ID` - ID чата для получения уведомлений (опционально)

2. Запустите workflow вручную через вкладку Actions

## Возможности Telegram-бота

После настройки TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID, система будет отправлять уведомления о:

- Статусе запуска и завершения работы
- Ошибках с детальной информацией и скриншотами
- Статистике отправленных откликов

Бот также поддерживает команды:
- `/start` - приветственное сообщение с описанием возможностей
- `/status` - текущий статус системы
- `/last_errors` - последние ошибки (в будущих версиях)
- `/stats` - статистика за сегодня (в будущих версиях)

## Архитектура

Проект следует архитектуре с тремя уровнями абстракции:

1. **UI уровень (Page Objects)** - взаимодействие с элементами интерфейса
2. **Бизнес-логика** - логика выполнения конкретных задач
3. **Шаги/Сценарии** - высокоуровневые операции

### UI уровень (Page Objects)
- `src/pages/base_page.py` - базовый класс для всех страниц
- `src/pages/auth_page.py` - страница авторизации
- `src/pages/main_page.py` - главная страница
- `src/pages/resume_page.py` - страница резюме
- `src/pages/vacancy_page.py` - страница вакансий
- `src/pages/application_page.py` - страница отправки откликов

### Бизнес-логика
- `src/business_logic/auth_handler.py` - обработчик авторизации
- `src/business_logic/resume_handler.py` - обработчик резюме
- `src/business_logic/vacancy_handler.py` - обработчик вакансий
- `src/business_logic/application_handler.py` - обработчик откликов
- `src/business_logic/session_manager.py` - менеджер сессии

### Шаги/Сценарии
- `src/steps/auth_steps.py` - шаги авторизации
- `src/steps/resume_steps.py` - шаги работы с резюме
- `src/steps/vacancy_steps.py` - шаги работы с вакансиями
- `src/steps/application_steps.py` - шаги отправки откликов
- `src/steps/main_workflow.py` - основной сценарий

### Вспомогательные модули
- `src/config.py` - управление конфигурацией и переменными окружения
- `src/browser_config.py` - настройка опций браузера
- `src/error_handler.py` - обработка ошибок
- `src/logger.py` - логирование

> **Примечание:** Старые модули (`src/auth.py`, `src/navigation.py`, `src/vacancy_processor.py`, `src/application_sender.py`) помечены как устаревшие, но по-прежнему работают, используя внутренне новую архитектуру.
