# Поток выполнения кода hh_auto_responder

## Общий поток выполнения

Приложение `hh_auto_responder` реализует автоматизированный процесс отклика на вакансии на hh.ru. Ниже приведено
пошаговое описание потока выполнения кода.

## 1. Запуск приложения

Приложение запускается через `if __name__ == "__main__"` в файле `hh_auto_responder.py`, что вызывает асинхронную
функцию `main()`.

## 2. Инициализация

### 2.1. Настройка логгера

- Вызов `setup_logger()` из модуля `src/logger.py`
- Создается логгер с форматированием и выводом в консоль

### 2.2. Загрузка конфигурации

- Вызов `get_config_from_env()` из модуля `src/config.py`
- Загружаются переменные окружения: логин, пароль, настройки браузера и т.д.
- Если обязательные переменные отсутствуют, выбрасывается исключение `ValueError`

### 2.3. Настройка браузера

- Вызов `get_browser_options()` и `get_browser_context_options()` из модуля `src/browser_config.py`
- Подготавливаются опции для запуска браузера и создания контекста

## 3. Запуск браузера

### 3.1. Инициализация Playwright

- Создается контекст `async with async_playwright() as p`
- Запускается браузер Chromium с подготовленными опциями

### 3.2. Создание контекста и страницы

- Создается новый контекст браузера с подготовленными опциями
- Создается новая страница в контексте

## 4. Инициализация модулей

Создаются экземпляры всех основных классов:

- `HHAuth` из `src/auth.py` - для авторизации
- `HHNavigation` из `src/navigation.py` - для навигации
- `VacancyProcessor` из `src/vacancy_processor.py` - для обработки вакансий
- `ApplicationSender` из `src/application_sender.py` - для отправки откликов
- `ErrorHandler` из `src/error_handler.py` - для обработки ошибок

## 5. Процесс авторизации

### 5.1. Вызов `auth.perform_auth(page)`

- Переход на главную страницу hh.ru
- Клик по кнопке "Войти"
- Заполнение формы логина (email/телефон)
- Клик по кнопке "Продолжить"
- Заполнение формы пароля
- Клик по кнопке "Войти"
- Проверка успешной авторизации

## 6. Навигация к вакансиям

### 6.1. Переход к разделу рекомендаций

- Вызов `navigation.navigate_to_my_resumes(page)` - переход на страницу "Мои резюме"

### 6.2. Выбор резюме

- Вызов `navigation.select_first_resume(page)` - выбор первого резюме на странице

### 6.3. Переход к рекомендуемым вакансиям

- Вызов `navigation.go_to_recommended_vacancies(page, "resume123")` - переход к рекомендуемым вакансиям
- Вызов `navigation.wait_for_vacancies_loaded(page)` - ожидание загрузки вакансий

## 7. Обработка вакансий

### 7.1. Поиск вакансий

- Вызов `processor.find_vacancy_cards(page)` - поиск всех карточек вакансий на странице
- Создание списка локаторов для каждой вакансии

### 7.2. Фильтрация вакансий

- Вызов `processor.filter_applicable_vacancies(vacancy_locators)` - фильтрация вакансий по возможности отклика
- Только вакансии с доступной кнопкой отклика будут обработаны

## 8. Отправка откликов

### 8.1. Цикл по подходящим вакансиям

Для каждой вакансии из списка `applicable_vacancies`:

#### 8.1.1. Вызов `sender.apply_to_vacancy(vacancy)`

- Получение информации о вакансии (название, ID)
- Клик по кнопке отклика с помощью `click_apply_button()`
- Ожидание результата отклика с помощью `wait_for_application_result()`
- Логирование результата с помощью `log_application_result()`
- Пауза между откликами для имитации человеческого поведения

## 9. Обработка ошибок

### 9.1. Обработка ошибок во время работы

- Если происходит ошибка во время работы скрипта, вызывается `error_handler.handle_general_error(page, e)`
- Создается скриншот ошибки
- Ошибка логируется

### 9.2. Обработка критических ошибок

- Если происходит критическая ошибка при запуске браузера, также создается скриншот
- Приложение завершается с кодом 1

## 10. Завершение работы

### 10.1. Закрытие браузера

- В блоке `finally` вызывается `await browser.close()` для корректного закрытия браузера
- Логируется завершение работы

## Асинхронный поток выполнения

Все основные операции являются асинхронными и используют `async/await`:

- Операции с браузером (переходы, клики, ожидания)
- Взаимодействие с DOM элементами
- Ожидание загрузки страниц и элементов
- Паузы между действиями

## Обработка исключений

Приложение использует многоуровневую обработку исключений:

- На уровне отдельных операций (например, при попытке клика по элементу)
- На уровне модулей (внутри каждого класса)
- На уровне основного процесса (в функции `main`)
- На уровне критических ошибок (при запуске браузера)

## Взаимодействие между модулями

Модули взаимодействуют друг с другом через передачу объекта страницы Playwright:

- Модуль авторизации изменяет состояние страницы (авторизует пользователя)
- Модуль навигации перемещает пользователя по страницам
- Модуль обработки вакансий анализирует содержимое страницы
- Модуль отправки откликов взаимодействует с элементами на странице
