# План рефакторинга hh_auto_responder

## Цель рефакторинга
Переход к архитектуре с тремя уровнями абстракции:
1. **UI уровень (Page Objects)** - взаимодействие с элементами интерфейса
2. **Бизнес-логика** - логика выполнения конкретных задач
3. **Шаги/Сценарии** - высокоуровневые операции

## Текущая архитектура
- Весь код находится в `/src/`
- Смешение UI логики и бизнес-логики
- Модули: `auth.py`, `navigation.py`, `vacancy_processor.py`, `application_sender.py`, `error_handler.py`, `logger.py`, `browser_config.py`, `config.py`

## Новая архитектура

### 1. UI уровень (Page Objects) - `/src/pages/`
- `base_page.py` - базовый класс для всех страниц
- `auth_page.py` - страница авторизации
- `main_page.py` - главная страница hh.ru
- `resume_page.py` - страница резюме
- `vacancy_page.py` - страница вакансий
- `application_page.py` - страница отправки отклика

### 2. Бизнес-логика - `/src/business_logic/`
- `auth_handler.py` - обработчик авторизации
- `resume_handler.py` - обработчик резюме
- `vacancy_handler.py` - обработчик вакансий
- `application_handler.py` - обработчик отправки откликов
- `session_manager.py` - менеджер сессии

### 3. Шаги/Сценарии - `/src/steps/`
- `auth_steps.py` - шаги авторизации
- `resume_steps.py` - шаги работы с резюме
- `vacancy_steps.py` - шаги работы с вакансиями
- `application_steps.py` - шаги отправки откликов
- `main_workflow.py` - основной сценарий

## Потенциальные проблемы и решения
- **Проблема**: Сложность в определении границ между уровнями
  - **Решение**: Четко определить, что UI уровень отвечает за взаимодействие с элементами, бизнес-логика за логику выполнения задач, а шаги за сценарии выполнения

- **Проблема**: Необходимость обновления всех зависимостей
  - **Решение**: Поэтапный рефакторинг с сохранением обратной совместимости на каждом этапе

## Временные рамки
- Оценочное время выполнения: 3-5 дней в зависимости от сложности
- Требуется тестирование после каждого этапа
