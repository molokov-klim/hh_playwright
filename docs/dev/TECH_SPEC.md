### **Техническое задание (ТЗ): Автоматизация массовых откликов на hh.ru**

**1. Цель проекта**
Разработать автоматизированный скрипт на Python с использованием Playwright, который авторизуется на сайте hh.ru под
моим аккаунтом, переходит к рекомендациям по моему резюме и отправляет отклики на все предложенные вакансии. Скрипт
должен быть готов к запуску в среде GitHub Actions.

**2. Требования к окружению и инструментам**

* **Язык программирования:** Python 3.10+
* **Фреймворк для автоматизации:** Playwright (синхронная или асинхронная версия - на усмотрение разработчика, с
  обоснованием выбора в комментариях).
* **Управление зависимостями:** `pyproject.toml` + `uv`.
* **Запуск в CI/CD:** GitHub Actions (необходимо создать конфигурационный файл `.github/workflows/run-hh-bot.yml`).
* **Безопасность:** Логин и пароль от аккаунта hh.ru должны передаваться через **секреты GitHub Actions (Secrets)** и
  переменные окружения в скрипте. Никогда не хардкодить в код.
* **Linting:** Ruff + Pyright

**3. Детальные требования к функционалу скрипта**

**3.1. Инициализация и настройка**

* Скрипт должен принимать логин и пароль через переменные окружения:
    * `HH_LOGIN` (это email или телефон)
    * `HH_PASSWORD`
* Необходимо использовать headless-режим браузера для работы в GitHub Actions. Режим должен переключаться (например,
  через аргумент командной строки `--headed`) для локальной отладки.
* Браузер должен быть настроен с учетом возможных "анти-бот" проверок (например, увеличенный `viewport`, передача
  `user-agent`). Использовать контекст браузера.

**3.2. Процесс авторизации**

1. Переход на `https://hh.ru`.
2. Клик по кнопке "Войти" и переход на форму входа.
3. **Вариант 1 (Предпочтительный):** Заполнение поля "Электронная почта или телефон" и нажатие "Продолжить". Затем
   заполнение поля "Пароль" и нажатие "Войти".
4. **Вариант 2:** Если сайт предлагает другую логику (например, выбор аккаунта), алгоритм должен быть адаптивным.
5. Обязательная **явная проверка успешной авторизации**. Ожидание появления элемента, уникального для авторизованной
   сессии (например, аватарки пользователя в шапке, ссылки "Мои резюме").

**3.3. Навигация к разделу рекомендаций**

1. После входа необходимо перейти на страницу "Мои резюме". URL: `https://hh.ru/applicant/resumes`.
2. Поскольку резюме одно, нужно кликнуть по нему, чтобы перейти на его детальную страницу.
3. На странице резюме найти и кликнуть по разделу/вкладке/кнопке "**Рекомендуемые вакансии**" (обычно это
   `https://hh.ru/applicant/resumes/{resume_id}/recommended`).

**3.4. Массовая отправка откликов**

1. На странице рекомендаций необходимо собрать все карточки вакансий, доступные для отклика.
2. **Важно:** Откликаться только на вакансии, где есть кнопка "Откликнуться" (или аналогичная). Пропускать вакансии, где
   есть кнопка "Заполнить анкету" или "Отклик без резюме", если они требуют дополнительных действий.
3. Для каждой подходящей вакансии:
    * Прокрутить карточку в область видимости.
    * Кликнуть по кнопке "Откликнуться" (или "Откликнуться одним резюме", если появится модальное окно выбора).
    * **Ожидать результат отклика.** Проверить, что отклик прошел успешно (например, кнопка сменила состояние на "
      Отправлено", "Отклик отправлен", или появилось confirmation-сообщение).
    * Зафиксировать в логах результат по каждой вакансии (название, ID, статус: "Успешно", "Пропущена", "Ошибка").
    * Добавить небольшую паузу (например, `random.uniform(1.5, 4)`) между откликами для имитации человеческого поведения
      и снижения нагрузки на сервер.
4. Если встречается капча или любое неожиданное модальное окно — скрипт должен остановить выполнение, сделать скриншот (
   `page.screenshot()`), сохранить его как артефакт и завершиться с ошибкой.

**3.5. Логирование и обработка ошибок**

* Использовать модуль `logging` для информативных сообщений (INFO, WARNING, ERROR).
* Логировать ключевые этапы: "Начало авторизации", "Авторизация успешна", "Найдено N вакансий", "Отклик на вакансию [ID]
  успешен", "Завершение работы".
* Обернуть критичные части кода в `try/except`. При возникновении непредвиденной ошибки — логировать ее, делать скриншот
  и завершать выполнение.

**4. Требования к коду**

* **Читаемость:** Код должен быть хорошо структурирован, с комментариями к неочевидным моментам (например, выбор
  селекторов).
* **Селекторы:** Использовать `data-qa` атрибуты, если они есть на hh.ru (например, `[data-qa="login"]`). Если нет —
  стабильные CSS-селекторы. Избегать селекторов, которые могут часто меняться (например, инлайн-стили или динамические
  классы).
* **Ожидания (Waits):** Использовать встроенные ожидания Playwright (`page.wait_for_selector`, `page.wait_for_url`,
  `expect(locator).to_be_visible()`). Избегать `time.sleep()`.
* **Конфигурация:** Вынести в отдельный файл или секцию в начале кода конфигурируемые параметры (таймауты, базовые URL,
  селекторы).

**5. Настройка GitHub Actions (`.github/workflows/run-hh-bot.yml`)**

* **Название workflow:** `Run HH.ru Auto-Responder`
* **Триггер:** Ручной запуск (`workflow_dispatch`). *Дополнительно (опционально):* можно добавить запуск по расписанию (
  например, `cron: '0 8 * * 1'` - каждый понедельник в 8 утра).
* **Шаги (jobs):**
    1. Checkout кода.
    2. Установка Python.
    3. Установка зависимостей из `requirements.txt`.
    4. Установка браузеров для Playwright (`playwright install`).
    5. **Запуск скрипта**, передавая секреты в виде переменных окружения:
       ```yaml
       env:
         HH_LOGIN: ${{ secrets.HH_LOGIN }}
         HH_PASSWORD: ${{ secrets.HH_PASSWORD }}
       ```
    6. **Пост-обработка:** В случае падения скрипта — загрузка скриншотов и логов в качестве артефактов workflow для
       последующей отладки.

**6. Инструкция по развертыванию (для меня)**
Агент должен предоставить краткий `README.md` или секцию в ТЗ с шагами:

1. Клонировать репозиторий.
2. Создать виртуальное окружение Python и установить зависимости (`pip install -r requirements.txt`).
3. Установить браузеры Playwright (`playwright install`).
4. Протестировать скрипт локально, задав переменные окружения.
5. В настройках репозитория GitHub создать Secrets: `HH_LOGIN` и `HH_PASSWORD`.
6. Запустить workflow вручную через Actions tab.

**7. Ожидаемый результат работы**

* Python-скрипт с понятной структурой.
* Конфигурационный файл для GitHub Actions.
* Файл зависимостей (`requirements.txt`).
* Краткая инструкция по запуску.
