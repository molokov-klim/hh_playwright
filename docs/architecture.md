# Архитектура hh_auto_responder

## Обзор

`hh_auto_responder` - это автоматизированное решение для массового отклика на вакансии на сайте hh.ru. Проект использует Playwright для автоматизации браузера и предоставляет модульную архитектуру для выполнения различных задач, связанных с авторизацией, навигацией, обработкой вакансий и отправкой откликов.

## Структура проекта

## Архитектурные компоненты

### 1. Main Script (`hh_auto_responder.py`)

Основной скрипт, который координирует всю работу приложения. Он:

- Загружает конфигурацию из переменных окружения
- Инициализирует браузер с нужными параметрами
- Создает экземпляры всех модулей
- Последовательно выполняет шаги: авторизация → навигация → поиск вакансий → отправка откликов
- Обрабатывает ошибки и создает скриншоты при возникновении проблем

### 2. Configuration Module (`src/config.py`)

Содержит класс `Config` для хранения всех настроек приложения и функцию `get_config_from_env()` для загрузки конфигурации из переменных окружения. Поддерживает следующие параметры:

- `HH_LOGIN`: Логин для входа на hh.ru
- `HH_PASSWORD`: Пароль для входа на hh.ru
- `HEADLESS`: Режим работы браузера (headless или headed)
- `VIEWPORT_WIDTH`, `VIEWPORT_HEIGHT`: Размеры окна браузера
- `USER_AGENT`: User-Agent строки для имитации реального браузера
- `TIMEOUT`: Время ожидания для операций
- `RESUME_ID`: ID резюме (необязательный параметр)

### 3. Browser Configuration Module (`src/browser_config.py`)

Содержит функции для настройки опций браузера и контекста браузера:

- `get_browser_options()`: Возвращает опции для запуска браузера (headless режим, аргументы командной строки)
- `get_browser_context_options()`: Возвращает опции для создания контекста браузера (размеры окна, user-agent, таймауты)

### 4. Authentication Module (`src/auth.py`)

Класс `HHAuth` отвечает за процесс авторизации на hh.ru:

- `perform_auth()`: Основной метод для выполнения полного процесса авторизации
- `_fill_login_form()`: Заполняет форму логина (email/телефон)
- `_fill_password_form()`: Заполняет форму пароля
- `_check_auth_success()`: Проверяет успешность авторизации

### 5. Navigation Module (`src/navigation.py`)

Класс `HHNavigation` управляет навигацией по сайту:

- `navigate_to_my_resumes()`: Переходит на страницу "Мои резюме"
- `select_resume()`: Выбирает резюме по ID
- `select_first_resume()`: Выбирает первое резюме на странице
- `go_to_recommended_vacancies()`: Переходит к рекомендуемым вакансиям для выбранного резюме
- `wait_for_vacancies_loaded()`: Ожидает загрузки вакансий на странице

### 6. Vacancy Processor Module (`src/vacancy_processor.py`)

Класс `VacancyProcessor` обрабатывает вакансии:

- `find_vacancy_cards()`: Находит все карточки вакансий на странице
- `is_apply_button_available()`: Проверяет доступность кнопки отклика для вакансии
- `filter_applicable_vacancies()`: Фильтрует вакансии по возможности отклика
- `get_vacancy_info()`: Получает информацию о вакансии (название, ID)

### 7. Application Sender Module (`src/application_sender.py`)

Класс `ApplicationSender` отправляет отклики на вакансии:

- `click_apply_button()`: Кликает по кнопке отклика на вакансию
- `wait_for_application_result()`: Ожидает результат отклика
- `log_application_result()`: Логирует результат отклика
- `apply_to_vacancy()`: Полный цикл отклика на вакансию

### 8. Error Handler Module (`src/error_handler.py`)

Класс `ErrorHandler` обрабатывает ошибки:

- `create_error_screenshot_path()`: Создает путь для скриншота ошибки с временной меткой
- `take_screenshot_on_error()`: Создает скриншот при ошибке
- `handle_captcha_detection()`: Обрабатывает обнаружение капчи
- `handle_unexpected_modal_window()`: Обрабатывает неожиданное модальное окно
- `handle_general_error()`: Обрабатывает общую ошибку

### 9. Logger Module (`src/logger.py`)

Содержит функцию `setup_logger()` для настройки логгера с форматированием и выводом в консоль.

## Паттерны проектирования

### Протоколы типизации

Проект использует протоколы типизации для определения интерфейсов:

- `PageProtocol`: Определяет интерфейс для страницы Playwright
- `LocatorProtocol`: Определяет интерфейс для локатора Playwright

Это позволяет использовать статическую проверку типов и упрощает тестирование с моками.

### Разделение ответственности

Каждый модуль имеет четко определенную ответственность:

- Конфигурация: управление настройками
- Браузер: настройка параметров браузера
- Авторизация: логика входа на сайт
- Навигация: перемещение по страницам
- Обработка вакансий: анализ и фильтрация
- Отправка откликов: логика отправки
- Обработка ошибок: восстановление после проблем
- Логирование: запись событий

## Технологии

- **Python 3.10+**: Язык программирования
- **Playwright**: Автоматизация браузера
- **AsyncIO**: Асинхронное выполнение
- **Logging**: Система логирования
- **PyTest**: Тестирование
- **Typing**: Статическая проверка типов

## Безопасность

- Учетные данные передаются через переменные окружения
- Никакие чувствительные данные не хранятся в коде
- Используется HTTPS для всех соединений
- Обработка ошибок с созданием скриншотов для аудита

## Тестирование

Проект включает как модульные, так и интеграционные тесты:

- **Модульные тесты**: Проверяют отдельные компоненты
- **Интеграционные тесты**: Проверяют взаимодействие между компонентами
